# Changelog 格式规范

## 格式说明

changelog.md 使用 Markdown 列表格式记录每次修改。采用类似于 Conventional Commits 的规范。

## 条目结构

每个修改条目应包含以下信息：

```markdown
### [日期] [版本号] [类型]

**修改原因：**
[为什么进行这次修改？解决了什么问题或实现了什么功能？]

**修改内容：**
- [具体修改 1]
- [具体修改 2]
- [具体修改 3]

**影响范围：**
- 受影响的文件/模块

**相关提交：**
- `commit-id: 提交信息`
```

## 修改类型

- **新增** (feat): 新功能
- **修复** (fix): Bug 修复
- **优化** (perf): 性能优化
- **重构** (refactor): 代码重构（不改变功能）
- **文档** (docs): 文档更新
- **样式** (style): 代码格式调整（不影响代码运行）
- **测试** (test): 测试相关
- **其他** (chore): 构建、工具链等

## 示例

```markdown
## 2026-01-27 v1.2.3 修复

**修改原因：**
修复添加按钮被遮挡的问题，导致用户无法点击添加源。

**修改内容：**
- 调整 TimelineScreen 布局，增加底部间距
- 修改 Padding 设置，确保按钮可见
- 添加边缘测试用例

**影响范围：**
- ui/screens/TimelineScreen.kt

**相关提交：**
- 042fb88: 修复添加按钮的遮挡问题
```

## 注意事项

- 日期格式：YYYY-MM-DD
- 版本号：遵循语义化版本规范（Major.Minor.Patch）
- 使用中文描述
- 保持简洁明了
- 每个 changelog 条目对应一次 git 提交
