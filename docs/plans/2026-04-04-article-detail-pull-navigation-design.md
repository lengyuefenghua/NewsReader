# 详情页上下拉连续阅读设计

- 日期：2026-04-04
- 项目：NewsReader
- 范围：详情页新增顶部下拉上一篇、底部上拉下一篇的连续阅读交互
- 目标：在文章详情页中，基于进入详情时的列表顺序，提供自然的上下篇连续阅读体验

## 1. 背景

当前 `ArticleScreen` 只根据单篇文章 `url` 打开详情，详情页内部没有“当前文章在列表中的位置”这一上下文，因此无法支持上一篇/下一篇切换。

用户希望：

1. 在详情页阅读时，顶部下拉可切到上一篇
2. 底部上拉可切到下一篇
3. 交互中显示贴边、接近半圆的弧形提示区域
4. 弧形区域中显示上一篇/下一篇标题，或显示“已经没有文章了”的状态提示

## 2. 用户确认的交互约束

### 2.1 上下篇定义
采用“按进入详情页时的列表顺序”作为上一篇/下一篇判断依据。

这意味着：

1. 从时间线进入详情时，连续阅读遵循当前时间线顺序
2. 从单个订阅源列表进入详情时，连续阅读遵循该源列表顺序
3. 从收藏页进入详情时，连续阅读遵循收藏列表顺序

### 2.2 边界行为

1. 顶部下拉但当前已是第一条：不跳转，显示轻提示
2. 底部上拉但当前已是最后一条：不跳转，显示轻提示
3. 不采用“自动退出详情页”行为

### 2.3 视觉形态

采用“左右贴边、接近半圆”的弧形区域，而不是普通矩形提示条。

具体要求：

1. 顶部为向下鼓出的半圆弧面
2. 底部为向上鼓出的半圆弧面
3. 弧形区域宽度接近整屏，左右与内容区域贴近
4. 弧形区域内显示上下篇标题或到头提示

## 3. 方案对比

### 方案 A：仅做文字提示，不做弧形交互
- 优点：实现最简单
- 缺点：不符合已确认的视觉目标，连续阅读感弱

### 方案 B：简化弧形提示区 + 边界拖拽切换（推荐）
- 优点：满足弧形视觉、标题预览、上下篇切换需求
- 优点：改动集中在导航上下文和 `ArticleScreen`
- 缺点：需要处理 `WebView` 页顶/页底判断

### 方案 C：完整物理弹性拖拽 + 复杂路径形变
- 优点：视觉最强
- 缺点：实现复杂度高，`WebView + Compose` 场景下稳定性和调参成本大

### 推荐结论
采用方案 B：优先实现稳定、可控的“贴边半圆弧提示区 + 阈值释放切换”，不追求复杂物理弹性效果。

## 4. 现状诊断

### 4.1 路由层
`MainActivity.kt` 当前使用 `NavRoutes.article(url)` 打开详情页，仅传递文章 URL。

影响：

1. 详情页只能解析当前文章
2. 无法知道它来自哪个列表
3. 无法可靠计算上一篇/下一篇

### 4.2 详情页层
`ArticleScreen.kt` 当前主体是 `Scaffold + WebView`，已有顶部栏、底部工具栏和阅读时长统计，但没有边界拖拽手势状态。

影响：

1. 无法在页顶/页底接管继续拖拽
2. 无法展示拖拽进度对应的弧形提示区

### 4.3 数据层
`TimelineViewModel` 当前维护的是文章列表流，但 `ArticleScreen` 没有拿到“当前列表快照 + 当前 index”。

影响：

1. 上下篇需要依赖 UI 入口额外传递阅读上下文
2. 收藏页等非时间线路径也要统一接入同一上下文模型

## 5. 目标体验设计

### 5.1 顶部下拉上一篇

触发条件：

1. 当前网页滚动已到顶部
2. 用户继续向下拖拽

交互过程：

1. 页面整体下移
2. 顶部显示贴边半圆弧提示区
3. 提示区显示：
   - 有上一篇时：上一篇标题 + “释放查看上一篇”
   - 无上一篇时：已经是第一条 + 回弹提示
4. 达到阈值后松手：切换到上一篇
5. 未达到阈值：回弹，不切换

### 5.2 底部上拉下一篇

触发条件：

1. 当前网页滚动已到底部
2. 用户继续向上拖拽

交互过程：

1. 页面整体上移
2. 底部显示贴边半圆弧提示区
3. 提示区显示：
   - 有下一篇时：下一篇标题 + “释放查看下一篇”
   - 无下一篇时：已经是最后一条 + 回弹提示
4. 达到阈值后松手：切换到下一篇
5. 未达到阈值：回弹，不切换

## 7. 架构设计

### 7.1 新增阅读上下文模型
需要引入一个轻量的“详情页阅读上下文”模型，用于表达：

1. 当前详情页来自哪个列表
2. 当前文章在列表中的位置
3. 前后文章分别是谁

建议模型语义：

1. 列表中的文章 ID 或 URL 顺序集合
2. 当前文章唯一标识
3. 当前索引

首版不要求持久化，仅作为导航时的会话级上下文。

### 7.2 上下文来源

以下入口都要统一构造阅读上下文：

1. 时间线列表
2. 单订阅源列表
3. 收藏列表

每个入口在点击文章时，需要把“当前显示列表顺序”和“被点击文章位置”一起传给详情页，而不是只传 URL。

### 7.3 详情页内部状态
`ArticleScreen` 需要新增以下状态能力：

1. 当前是否处于顶部拖拽态
2. 当前是否处于底部拖拽态
3. 拖拽距离
4. 是否达到触发阈值
5. 上一篇/下一篇预览信息

### 7.4 与 WebView 的协作
要实现该功能，详情页必须在拖拽前先判断 `WebView` 是否已在顶部或底部。

建议判断方式：

1. 顶部：`scrollY == 0`
2. 底部：通过 `contentHeight * scale - height - scrollY` 接近 0 判断

只有在边界已触达时，才允许外层拖拽逻辑接管并展示弧形提示区。

## 8. 交互状态机

建议采用以下概念状态：

1. `Idle`
2. `PullingPrevious(progress)`
3. `PreviousReadyToRelease`
4. `PullingNext(progress)`
5. `NextReadyToRelease`
6. `Settling`

状态规则：

1. 同一时间只允许顶部或底部一个方向处于激活状态
2. 达阈值前文案为“继续拖动”或“释放查看”
3. 无上一篇/下一篇时，永远不会进入实际跳转状态

## 9. 视觉规范

### 9.1 形状

1. 宽度接近整屏
2. 左右贴边
3. 不是普通圆角卡片，而是自定义弧形路径
4. 顶部和底部各自为方向相反的半圆弧面

### 9.2 内容

1. 主文案：上一篇/下一篇标题，单行省略
2. 副文案：`释放查看上一篇` / `释放查看下一篇`
3. 边界文案：`已经是第一条` / `已经是最后一条`

### 9.3 动效

1. 拖拽越深，弧形高度越高
2. 未达阈值时松手，做回弹动画
3. 达阈值时，使用颜色或透明度变化强化“可释放”状态
4. 首版不做复杂弹簧形变，只做稳定的高度插值和淡入淡出

## 10. 最小改动落点

> 本节只定义未来实施范围，不代表当前已经实施。

### 10.1 `MainActivity.kt`

1. 详情页路由参数需要扩展，支持传递阅读上下文
2. 详情页进入方式要从“只传 URL”升级为“URL + 列表上下文”

### 10.2 `TimelineScreen.kt`

1. 点击文章时，不再只传 URL
2. 需要根据当前显示列表构造阅读上下文

### 10.3 `FavoritesScreen.kt`

1. 点击收藏文章时，同样构造阅读上下文
2. 保证收藏页连续阅读遵循收藏列表顺序

### 10.4 `ArticleScreen.kt`

1. 接收阅读上下文
2. 计算上一篇和下一篇
3. 接入顶部/底部边界拖拽逻辑
4. 绘制贴边半圆弧提示区
5. 达阈值后触发切换

### 10.5 可选新增文件
如实现中需要避免 `MainActivity` 和页面间参数过重，可新增一个小型的导航辅助模型或会话状态容器。

## 11. 明确不做

1. 不修改数据库 schema
2. 不持久化阅读上下文到数据库
3. 不引入复杂手势物理引擎
4. 不改变现有详情页底部工具栏信息结构
5. 不改变文章排序规则本身，只复用用户进入时的列表顺序

## 12. 风险与缓解

1. `WebView` 边界判断不稳定
   - 缓解：封装顶部/底部检测条件，增加容差，不直接依赖单一瞬时值

2. 路由参数过大
   - 缓解：不要直接通过导航字符串传完整文章对象列表，优先传 ID/URL 列表或使用会话态容器

3. 从多个入口进入详情时行为不一致
   - 缓解：统一阅读上下文模型，由所有入口共用同一构造逻辑

4. 手势与 WebView 原生滚动冲突
   - 缓解：仅在页顶/页底后才接管继续拖拽，其他时机完全交给 WebView

## 13. 测试与验证建议

实施后应重点验证：

1. 从时间线进入详情，顶部下拉能否切上一篇
2. 从时间线进入详情，底部上拉能否切下一篇
3. 从单订阅源进入详情，连续阅读是否保持该源顺序
4. 从收藏进入详情，连续阅读是否保持收藏顺序
5. 第一条和最后一条边界提示是否正确
6. 拖动不足阈值时是否稳定回弹
7. WebView 内容较长、较短时页顶/页底检测是否稳定

## 14. 结论

本设计推荐以“阅读上下文 + WebView 边界拖拽 + 贴边半圆弧提示区”为最小完整方案，为详情页增加上下篇连续阅读能力。

该方案满足以下已确认目标：

1. 顶部下拉进入上一篇
2. 底部上拉进入下一篇
3. 按进入时列表顺序连续阅读
4. 到头时不跳转，仅提示
5. 显示左右贴边、接近半圆的弧形提示区域
